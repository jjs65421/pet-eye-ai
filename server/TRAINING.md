# 확정 라벨 기반 재학습

현재 네 질환 비교 모델의 추가 학습·비교 결과는 [MODEL_COMPARISON.md](MODEL_COMPARISON.md)에 있습니다. 아래 이진 모델의 점수 순위 방식은 이전 단계이며, 새 비교 모델이 적용되면 네 질환을 함께 학습한 분류 결과를 사용합니다.

기존 모델은 수의사 1차 라벨(`label_disease_lv_1`)로 학습했고, 서로 다른 모델의 최고 점수를 질환 확률처럼 표시했습니다. 새 과정은 확정 라벨(`label_disease_lv_3`)을 사용하며, 점수를 확률이나 신뢰도로 표시하지 않습니다.

추가로 TF 2.7의 HDF5 모델 복원에서 EfficientNet의 Normalization 내부 계산값이 복원된 가중치와 달라지는 문제를 실제 점수 비교로 확인했습니다. `model_loading.py`에서 복원 후 정규화 상태를 다시 구성합니다. 다섯 모델 모두 저장된 평가 점수와 실제 이미지 추론 점수의 최대 차이가 0.000004보다 작았습니다. 향후 재학습에서도 저장 모델의 출력 일치를 확인한 뒤 완료 처리합니다.

## 실행

서버 폴더에서 `train_all.bat --rebuild-manifest`를 실행합니다. 원본 D: 드라이브는 읽기만 하고, 생성된 색인과 특징 캐시는 `training_data/`, 학습 결과는 `models/confirmed-.../`에 저장합니다. GPU 환경은 기존 `pet-eye-gpu` 환경을 사용합니다.

다섯 모델의 저장과 평가가 끝나면 `models/active_models.json`이 완성된 실행 결과를 가리킵니다. 기존 모델 파일은 보존합니다. `run_server.bat`로 서버를 다시 실행하면 새 코드와 모델이 적용됩니다. `/health`의 `model_version`과 `smartphone_validated_models`로 확인할 수 있습니다.

## 데이터와 평가

- 라벨이 없거나 알 수 없는 값인 사진, 삭제된 라벨, 초음파 사진은 제외합니다.
- 같은 원본 이미지 파일 이름의 사진은 같은 분할에 배치합니다. 원본 이미지가 공식 평가 자료와 겹치면 학습에서 제외합니다. 동물 식별자가 없어 같은 동물의 서로 다른 사진까지 분리됐다고 보장할 수는 없습니다.
- 원래 학습 자료의 15%를 판단 기준 설정에 사용합니다. 공식 Validation은 평가용으로 유지하고, 원래 학습 자료의 스마트폰 사진 중 별도의 15%를 모델 학습 전에 평가용으로 남깁니다. 유루증 스마트폰 양성 사진이 공식 Validation에 없기 때문입니다.
- 모든 단계에서 EXIF 방향 적용, RGB 변환, 224×224 bilinear 크기 변환, 0~255 float32 입력을 동일하게 사용합니다. EfficientNet 내부에 픽셀값 변환이 있으므로 추가로 255로 나누지 않습니다.
- ImageNet EfficientNetB0의 고정된 특징을 한 번 추출하고, 질환별 이진 분류기를 새로 학습합니다. 정상/질환 가중치와 각 클래스 안의 장비 가중치를 맞춥니다. 한 장비에 정상·질환이 모두 없으면 가중치만으로 편향이 해결되지는 않습니다.
- 질환과 촬영 장비마다 판단 기준을 따로 정하고, 별도 평가에서 정상·질환이 각각 30장 이상일 때만 사용 가능 여부를 판단합니다. 기준 설정은 calibration 자료에만 사용하고 평가 자료로 임계값을 수정하지 않습니다.
- 개발 정책은 AUC ≥ 0.80, 이상 징후 기준의 특이도 ≥ 0.90와 민감도 ≥ 0.50, 낮은 점수 기준의 민감도 ≥ 0.90와 특이도 ≥ 0.10입니다. Calibration 기준은 특이도/민감도 각각 0.95를 목표로 합니다. 이것은 임상 검증 또는 앱 전체의 정확도 보장이 아닙니다.

## 앱과 서버의 판정

앱 업로드는 `photo_source=스마트폰`으로 요청합니다. 유루증은 촬영 방식별 검증 기준에 따라 이상 징후 가능성, 기준 미만, 판단 보류 중 하나로 따로 표시합니다. 백내장·핵경화·안검염·결막염 네 질환은 점수를 높은 순서로 표시하고, 이 네 항목 중 최고 점수를 대표 항목으로 보여줍니다. 유루증은 네 항목의 순위에 포함되지 않습니다. 앱의 0~100점은 모델 출력에 100을 곱한 참고 점수이며 질환 확률이 아닙니다. 각 모델의 척도가 달라 최고 점수가 실제로 가장 가능성이 높은 질환이라고 해석할 수 없습니다. 검증되지 않은 항목에도 미검증·참고용 표시를 붙입니다.

질환별 평가 기준과 `decision`/`validated` 정보는 유지합니다. 검증되지 않은 항목은 점수가 높아도 검증된 이상 징후(`flagged_diseases`)로 분류하지 않습니다. `epiphora_finding`은 유루증 선별 결과, `ranked_findings`는 네 질환의 참고 점수 순위, `top_finding`은 그 네 항목 중 최고 점수입니다. 전체 응답은 `hybrid_screening`입니다. 수의사 확인 권고는 참고 점수 표시 시 공통 안내이며 점수로 정한 긴급도나 질환 확정 판정이 아닙니다. 낮은 점수로 정상 판정을 내리지 않습니다.

`/docs`에서 실제 일반카메라 또는 검안경으로 찍은 데이터 사진을 검사할 때만 해당 `photo_source`를 선택합니다. 스마트폰 사진의 결과를 얻으려고 장비 값을 바꾸면 평가 범위를 벗어납니다. 사진 유사도 검사는 눈 사진 여부나 임상적 적합성을 검증한 장치가 아닙니다.

`validation_report.json`의 `by_device`가 실제 사용 범위를 결정합니다. 촬영 장비와 질환이 서로 얽혀 있으므로 장비를 섞은 높은 AUC만 보고 성능을 판단하면 안 됩니다. 초기 개발 평가에서 스마트폰 유루증은 AUC 약 0.912, 이상 징후 기준 민감도 약 62.8%, 특이도 약 94.0%였습니다. 질환 사진 중 약 37%가 이상 징후 기준을 넘지 못했으므로 결과만으로 질환을 배제할 수 없습니다. 나머지 네 질환의 스마트폰 성능은 확인할 수 없었습니다.

`test_screening.py`는 라벨 누락, 이미지 중복, 판정 보류, 복수 항목 표시, 전처리 일치와 API 판정 회귀를 검사합니다. `evaluate_models.py`는 저장된 평가 예측값으로 결과를 재계산하고, `verify_inference.py`는 실제 저장 모델의 출력이 평가 때의 점수와 일치하는지 검사합니다.

이 과정으로 해결되는 것은 라벨/전처리/결과 해석의 오류와 기존 데이터에서 평가 가능한 범위의 모델 학습입니다. 새로운 반려동물이나 휴대폰 촬영 환경에 대한 실제 성능은 외부 평가로 확인해야 합니다.
